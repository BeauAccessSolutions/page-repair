## Findings

### PR-1 · P2 · Upstream error bodies are logged and can echo request content
`proxy/src/index.ts:299-300`

```ts
const detail = (await apiRes.text()).slice(0, 300);
console.log(JSON.stringify({ event: 'anthropic_error', status: apiRes.status, detail }));
// Don't leak upstream details to the client beyond the status class.
```

Anthropic 4xx bodies can quote the offending request. The prompt carries allowlisted control context
including `href` (300 chars), `innerHtml` (300) and `nearbyText` (200) — which on an authenticated
page can carry identifying content. `observability.head_sampling_rate: 1` retains 100% of these in
Workers Logs.

The comment on the very next line is the tell: the leak boundary **was** considered — client-ward —
and the upstream detail was routed to the logs instead. Logs are a destination too.

**Why P2 rather than P1** (the same class was P1 in Benefits Navigator and KindredAccess): the
payload here is allowlist-filtered and length-capped before it ever reaches the prompt, so the worst
case is a few hundred characters of structured control context — not a whole document or chat
message sitting in a stack frame.

**Fix:** log `apiRes.status` plus an error `type` parsed from the body, not the raw body.

### PR-2 · P2 · Refund failures on the money path are silently swallowed
`proxy/src/index.ts` — the `refund` closure:

```ts
const refund = () => account.refund().then(() => undefined).catch(() => {});
```

The catch is **empty**, and `refund` is invoked from four `ctx.waitUntil()` sites covering every
upstream-failure path (unreachable, non-OK, model refusal, malformed output).

**Failure scenario:** Anthropic returns 502, the Worker spends a credit and calls `refund()`, the DO
call fails or the isolate is evicted before `waitUntil` settles. The user has **permanently lost a
paid credit** and there is no log line, no metric and no retry. Nobody can even count how often it
happens.

The `.catch()` itself is right — an unhandled rejection inside `waitUntil` would be worse. Swallowing
silently is the wrong trade on a path that moves real money.

**Fix:** log the failure. Log the error **type**, not `String(e)` — matching the pattern
KindredAccess already uses at `core/photo_moderation.py:274`, and avoiding the PR-1 class.

## What is right here, recorded deliberately

An audit that lists only defects mis-trains the next reader. These are patterns the rest of the
portfolio should copy:

- **The credit ledger is correct under concurrency.** `CreditsAccount.spend()` uses a conditional
  `UPDATE account SET balance = balance - 1 WHERE id = 0 AND balance > 0 RETURNING balance`; zero
  rows returned means the balance was already 0, so no over-spend slips through. The comment explains
  exactly that. Schema init is wrapped in `blockConcurrencyWhile`.
- **`crypto.subtle.timingSafeEqual` on `ADMIN_SECRET`** (`:125-131`, used at `:350`), hashing both
  sides first so length differences don't leak either.
- **`crypto.randomUUID()`** for token minting (`:364`) — not `Math.random()`.
- **`Env` is generated** by `wrangler types`, and the DO binding is typed
  `DurableObjectNamespace<CreditsAccount>` — not hand-written.
- **`extends DurableObject<Env>`** with `this.ctx.storage` — correct base-class usage, not `implements`.
- **`sanitizeContext` is an allowlist, not a denylist** (`:57-83`): eight named fields, each length-
  capped, plus at most 5 `dataAttrs`. **`value` is not on the list**, so a user's typed input never
  leaves the browser. Getting this shape right is the difference between "we strip what we thought of"
  and "only what we named can escape."
- Secrets via `wrangler secret put`, documented in `wrangler.jsonc` comments and absent from source.
- No `ctx` destructuring, no `passThroughOnException`, no module-scope mutable request state,
  structured JSON logging, `observability` enabled, `nodejs_compat` on, `compatibility_date` recent.
